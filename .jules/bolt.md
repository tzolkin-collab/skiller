## 2024-05-15 - [Database] Add missing foreign key indexes to prevent sequential scans
**Learning:** Drizzle ORM does not automatically create database indexes for foreign key constraints in Postgres. In this codebase's architecture, tables like `skills`, `mcp_sessions`, and `mcp_devices` are frequently queried by `userId` (e.g., `where(eq(skills.userId, userId))`). Without explicitly defining `index(...).on(table.userId)`, Postgres falls back to sequential scans for these lookups, creating an N+1 query-like bottleneck that degrades performance as the number of rows increases.
**Action:** When adding new foreign key relationships in `backend/src/db/schema.ts` that will be used for filtering or joins (especially user-related queries), always explicitly define an index using `index('table_col_idx').on(table.column)`.
